# IMPERIUM

ラテン語で指揮権・統率権を意味する**IMPERIUM**は、自分のAIワークスペースを構成するローカル運用ターミナルです。空のキャンバスに自分、AI、役割、記憶を追加し、Codex・Claude Codeなどの待機列、実行状況、ツールのイベント、結果を確認できます。会社の組織図は任意の構成であり、名前と肩書きは自由に決められます。

v1.3.1は**内部検証の対象バージョン**です。機能の拡張に伴い、v1.2.0の最終外部配布は行わず次のバージョンを準備します。ベンチマークと配布の検証が完了するまで、外部向けリリースは公開しません。以下のファイル名と更新手順はビルド・配布の対象を示すもので、公開ダウンロードが提供済みという意味ではありません。

ローカルWebサーバーをデスクトップのウィンドウまたはブラウザーで利用します。このアプリから開始したタスクを追跡します。既存のChatGPT・Claudeの会話や、別のターミナルで動くセッションを監視する機能はありません。

## デスクトップ版の起動

Windowsの内部検証用インストーラーは**`Imperium-Setup-1.3.1-x64.exe`**という形式で、セットアップウィザードを含みます。

1. インストーラーを実行し、**次へ（Next）→ インストール（Install）→ 完了（Finish）**の順に進みます。インストール先を変更でき、現在のWindowsユーザー用にインストールされます。
2. デスクトップまたはスタートメニューの**IMPERIUM**ショートカットからアプリを開きます。
3. アンインストールする場合は、Windowsの設定のアプリ一覧から**IMPERIUM**を選択します。

インストールせずに使用する場合は、ポータブル版の`Imperium-1.3.1-win-x64.exe`を選択してください。どちらも専用ウィンドウで開きます。モデルとの接続には、以下のCodex・Claude Codeのインストールとサブスクリプションでのログインが必要です。

非公開のソースリポジトリーにアクセスできる開発者は、Actionsの**Build Imperium desktop**を実行し、成功した実行の**Artifacts**からOSに合った検証用ファイルを取得できます。Windowsは`imperium-windows-x64`、macOSは`imperium-macos-intel-apple-silicon`、Linuxは`imperium-linux-x64`です。macOS用のDMG・ZIPは、macOSランナーでのビルド成功後に取得できます。Apple Silicon版のファイル名は`Imperium-1.3.1-mac-arm64.dmg`・`.zip`、Intel版は`Imperium-1.3.1-mac-x64.dmg`・`.zip`です。

作成者メタデータの名前は**Sato Junichiro**です。このメタデータだけでは、Windowsに確認された発行元にはなりません。実際のAuthenticode証明書を提供して署名するまでは未署名の開発用ビルドであり、Windowsで不明な発行元と表示される場合があります。Windowsでセキュリティ通知が出た場合は、配布元を確認したうえで、そのアプリのみ実行を許可してください。macOSでブロックされた場合は、システム設定の「プライバシーとセキュリティ」で、そのアプリのみ開くことを許可できます。OS全体のセキュリティ機能を無効にする必要はありません。

デスクトップ版の記録は、OSのアプリデータ保存先の`hq-data/`に保存されます。新規インストールの初期作業フォルダーはホーム内の`Imperium Projects/Workspace`で、新しいプロジェクトもホーム内の`Imperium Projects`に作成します。既存の保存済み設定は維持します。**プロジェクト（F9）**から、名前と色を指定して別の実作業フォルダーを作成・選択できます。

## Linuxへのインストール

Linux x64のビルド対象は、Debian・Ubuntu用の`Imperium-1.3.1-linux-amd64.deb`と、直接実行する`Imperium-1.3.1-linux-x86_64.AppImage`です。検証用パッケージを受け取った場合は、そのファイルがあるフォルダーで必要なコマンドを実行してください。

Debian・Ubuntuにインストールする場合：

```sh
sudo apt install ./Imperium-1.3.1-linux-amd64.deb
```

インストール後は、アプリメニューの**IMPERIUM**から起動できます。AppImageを使用する場合：

```sh
chmod +x Imperium-1.3.1-linux-x86_64.AppImage
./Imperium-1.3.1-linux-x86_64.AppImage
```

AppImageは、アプリメニューやデスクトップのショートカットを自動作成しません。LinuxでもCodex・Claude Codeのインストールとサブスクリプションでのログインが必要です。LinuxのCIビルド成功はパッケージの生成と自動検査を意味し、Linuxデスクトップでの手動実行テストを意味するものではありません。

## ソースからWebモードを起動

[Node.js](https://nodejs.org/) 22以上が必要です。このバージョンは実ターミナルやExcel書き出しの依存パッケージを使用するため、先にアプリのフォルダーでインストールしてください。

```sh
npm ci
npm start
```

[http://127.0.0.1:4310](http://127.0.0.1:4310)を開きます。Windowsでは`start-headquarters.cmd`からも起動できます。終了するには、サーバーのターミナルで`Ctrl+C`を押します。

サーバーを起動したまま別のターミナルで以下を実行すると、キーボードで操作するANSIターミナル表示も利用できます。

```sh
npm run terminal
```

環境変数`HQ_PORT`で、既定のポート4310を変更できます。

## サブスクリプションの接続

利用するCLIをインストールし、契約中のアカウントでログインします。以下の個別ツールは、アプリ本体の`npm ci`依存関係とは別にインストールします。

```sh
npm install -g @openai/codex
codex login
```

```sh
npm install -g @anthropic-ai/claude-code
claude auth login
```

CodexではChatGPTアカウント、Claude CodeではClaudeのサブスクリプションアカウントを選択します。アプリの接続画面からインストール・ログイン状況を更新できます。片方だけ準備できている場合は、タスクの指示時にそのモデルを選択してください。

Codex・Claude Codeでサブスクリプションのログインを選んだ場合、個別のAPIキーなしで、そのアカウントの条件と利用枠が適用されます。[OpenAIの公式案内](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)と[Claudeの公式案内](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan)を確認してください。モデルIDを指定した接続はそのIDを使い、空欄ならCLIの既定値を使います。プラン名に合わせてモデルや推論強度を強制しません。モデル利用権限、追加料金、クレジットの条件は各サービスが決定し、IMPERIUMは無料利用や費用削減を保証しません。

**AI接続（F5）**では、Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、Ollamaの5つのプロバイダーを登録できます。各ユーザーは自分のコンピューターとOSユーザーアカウントで公式CLIにログインします。同じOSユーザーの接続は、そのプロバイダーのCLIログインを共有します。表示名を複数登録しても、独立した認証アカウントが作成されるわけではありません。中央サーバーで複数人の契約アカウントを共有するサービスではありません。

モデル一覧の**アカウントから取得**、**CLIエイリアス**、**ローカルモデル**、**直接入力**は、それぞれ異なる情報源を示します。エイリアスや手入力のIDは、アカウントの利用権限を確認した証拠ではありません。自動取得できない場合は、公式CLIで利用可能なモデルを確認してIDを入力します。Gemini CLIのインストール検出だけでは認証を確定できない場合があるため、公式CLIでGoogleアカウントのログインを確認してください。Ollamaはこのコンピューターにインストールされたローカルモデルを使用します。

## 業務の指示

新しいワークスペースの最初の画面は**空のキャンバス（F1）**です。**ノードライブラリー**から自分、AI、役割、記憶を追加します。自分の名前や肩書きは自由で、「本部長」は必須ではありません。各AIのネームプレートで接続と役割を識別できます。会社型の配置を希望するときだけ、**組織テンプレート**を明示的に適用します。既存プロジェクトは保存済みのキャンバスを復元します。

1. **プロジェクト（F9）**で対象を選ぶか、名前・色・親フォルダーを指定して実際の新規フォルダーを作成します。新規プロジェクトは空の構成から始まります。
2. **AI接続（F5）**でCLIのインストール・ログインを確認し、キャンバスに必要なAIと役割を追加します。**業務を指示**はその役割を選んだタスク画面に移動するだけで、モデルを呼び出しません。**F2**でもタスク画面を開けます。
3. 指示を入力し、準備済みのプロバイダー・接続を選択します。タスクごとに役割の既定モデルを変更できます。
4. 読み取り専用またはファイル変更の権限と優先度を選び、**指示を送信**して実タスクを開始します。
5. リアルタイムのログ、結果、状況を確認し、必要ならタスクを取り消します。記録はJSONまたは実際のExcelブック（`.xlsx`）で書き出せます。

役割・部署ノードは業務を割り当てる定義であり、常時稼働する独立したモデルプロセスではありません。エージェント定義、キャンバス、記憶はプロジェクトごとに分かれます。登録したモデル接続とCLIログインは同じOSユーザーのプロジェクト間で共有されます。プロジェクトの切り替えで別の契約アカウントが作成されるわけではありません。待機中・実行中のタスクを完了または取り消してから切り替えてください。

キャンバスの実行・完了状態は実際のタスク状態に従います。AIが公開した段階・進捗率・残り時間は**モデルの推定**として区別し、正確な完成度や終了時刻を保証しません。過去のタスクから計算する時間も**履歴に基づく推定**です。実際の完了を確認したタスクだけを100%と表示します。

モデルごとに同時実行は1件、全体では最大2件です。同じ部署のタスクも順番に実行します。ファイル変更タスクは競合を減らすため、他のタスクと重ならないように実行します。全体の同時実行数は1または2に設定できます。

**DEMO**はモデルを呼び出さない、明示的に表示されたシミュレーションです。デモの実行・削除からストリーミングと状態変化を確認できます。実際のモデルは、ユーザーが実タスクを指示した場合に呼び出されます。

## ノード・記憶・ワークフロー

- ノードをドラッグして配置を変えます。背景のドラッグやホイールで移動し、`Ctrl+ホイール`で拡大・縮小できます。**全体表示**・**自動配置**も利用でき、位置と接続はプロジェクトごとに保存されます。
- **記憶を追加**から既存の記憶を選択するか、新しい記憶を作成します。記憶の出力ポートを部署の入力ポートにつなぐと、作業文脈として渡します。検査パネルで内容・固定状態・改訂番号を確認して編集できます。**キャンバスから除外**しても記憶自体は削除されません。
- 役割の出力を別の役割の入力につなぐと、業務の引き継ぎになります。循環する接続は作成できません。接続線を選択して削除できます。
- 接続だけでは作業を実行しません。部署を選んで指示を記入するか、検査パネルの**接続したフローを実行**から明示的に開始してください。既定の権限は読み取り専用です。

記憶は、ローカルファイルに保存するプロジェクト別のノート・決定・制約・タスク結果です。**ナレッジ（F11）**では、実際のタスク結果や固定したノートのグラフを確認できます。検索と自動関連付けは**プロジェクト範囲のキーワードRAG**であり、モデルの重みを学習させません。自動収集した結果は`unverified`資料です。人が原文を確認・修正し、重要なノートを固定してください。エージェントは固定済み・ユーザー作成の内容を上書きできません。固定自体が事実の正確さを自動検証するわけではありません。

Codex・Claudeのタスクには、実行中にも記憶を照会できる読み取り専用MCPツール`memory_search`、`memory_get`、`memory_list`を接続します。アクセスはそのタスクとプロジェクトに限定されます。モデルが必要に応じて照会する仕組みであり、毎回すべての記憶を読む、またはバックグラウンドで自律的に学習する機能ではありません。

## プロジェクトとローカル専用モード

**プロジェクト（F9）**は実際の新規フォルダーを作成します。既定の親フォルダーは現在の作業フォルダーの隣の`Imperium Projects`で、別の既存親フォルダーも指定できます。既存フォルダーを上書き・移動しません。名前と色は編集でき、役割定義・ノード配置・記憶の検索は選択中のプロジェクトに限定されます。

設定の**ローカル専用**（`settings.localOnly`）を有効にすると、このコンピューターのOllamaにインストールされたローカルモデルだけを実行します。クラウドタスクとクラウドモデル一覧の取得はHTTP 403で拒否し、デスクトップの更新確認・ダウンロードも停止します。待機中・実行中のタスクを終えてから設定を変更してください。この設定はアプリのモデル・更新経路に適用され、**実ターミナルで直接実行する外部コマンドやOS全体のネットワーク接続は遮断しません**。

## 使用量と性能

**分析（F10）**は現在のプロジェクトで保持する実タスクをもとに、トークン推移・タスク別グラフ、最初の出力までの遅延と実行時間のp50・p95、完了・失敗タスクの成功率を表示します。DEMOは除外し、CLIが使用量を報告しないタスクは未報告として扱います。欠損値を0や推定請求額に置き換えません。

以前・最近の比較は、同じプロバイダー・モデルID・役割・権限で使用量が報告された完了タスクが**6件以上**ある場合に行います。時系列の前半と後半から、各3件以上の同数を比較します。観測されたトークン変化であり、記憶機能の因果的効果や料金削減の証拠ではありません。モデルIDが不明なタスクは比較から除外します。契約の残りクレジット・利用可能率はCLIが公開しないため不明であり、トークン数を料金削減額に換算しません。

記憶の**初期文脈の文字選択率**は、保存された記憶に対して最初に渡した文字量を比較した値です。その後のMCP照会、CLI自身の文脈、トークン化を含む課金トークンの測定ではなく、実際の料金削減率を意味しません。設計の根拠と計測範囲は[構造と検証の原則](architecture.md)にまとめています。

## キーボードと実ターミナル

| キー | 画面・操作 |
| --- | --- |
| F1 / F2 / F3 / F4 | ノードワークスペース / タスク / 部署 / アクティビティ |
| F5 / F6 / F7 / F8 | AI接続・設定ガイド / ターミナル / 更新 / 一般設定 |
| F9 / F10 / F11 | プロジェクト / 分析 / ナレッジ |
| Ctrl+Enter | タスク入力欄から指示を送信 |
| / | タスクを検索 |

初回は**F5の設定ガイド**で、インストール → 公式アカウントのログイン → 実際の状態確認 → 明示的なサンプル体験の順に進めます。**ターミナルに準備**は、インストール・ログインコマンドを下書きとして渡すだけです。**F6**の**新しいセッション**で実シェルを開き、**ターミナルに入力（Enterなし）**を選択した後、シェルで自分で`Enter`を押して実行します。`Tab`・方向キーは実行中のシェルに送られ、`Ctrl+C`はそのプログラムに中断を要求します。下書き欄の`Enter`はコマンドを実行しません。

IMPERIUMの生のターミナル入出力は、セッションごとの容量制限付きRAMバッファーだけに保持します。アプリのタスク履歴・記憶・JSON・Excelには保存しません。**セッションを閉じる**操作でそのバッファーを破棄できます。実行したシェルやプログラム自体が作成する履歴・ファイル・ログは別です。

## Excelへの書き出し

`.xlsx`には、**概要・タスク・実行結果・部署・イベント・記憶・接続**の7シートが含まれます。シート名と見出しは韓国語・英語・日本語の選択に従います。元の指示と実際の結果を含み、長い結果はUTF-16で最大32,000文字の番号付き断片に分割して原文を保持します。使用量はCLIの報告値のみを記録し、認証トークン・APIキー・ターミナル出力・サーバー内部状態は除外します。ユーザーの文字列は数式ではなく文字セルとして保存します。

## 言語と権限

言語選択から、画面の表示文言と説明を한국어・English・日本語に切り替えられます。選択はアプリ設定とそのブラウザーに保存されます。モデルの回答は指示内容とサーバーの既定の韓国語指示に従うため、日本語などでの回答を希望する場合はプロンプトに明記してください。ユーザーが入力した部署名や役割も自動翻訳されません。

| 権限 | Codex | Claude Code |
| --- | --- | --- |
| 読み取り専用 | CLIの`read-only`サンドボックス | `Read`、`Glob`、`Grep` |
| ファイル変更 | CLIの`workspace-write`サンドボックス | 上記に加え`Edit`、`Write` |

Claudeでは`Bash`を許可しないため、現在のバージョンではシェルコマンドやテストを実行できません。CodexもCLIのサンドボックスと承認の制限を維持します。作業フォルダーは接続・設定画面から指定します。

Gemini CLI・GitHub Copilot CLI・Ollamaは、このバージョンでは**読み取り専用タスクのみ**対応します。ファイル変更権限を選んでも、これらのプロバイダーに書き込み権限は付与されません。実ターミナルは、ユーザーが直接操作する別のシェルです。

## 保存と現在の範囲

- Webモードのタスク、結果、イベント、設定、記憶、プロジェクト別ノード配置はGitの対象外となる`.hq/`に保存されます。デスクトップ版は上記のアプリデータ保存先を使用します。タスク履歴は最大200件です。
- サーバーを再起動すると、実行中・待機中のタスクは中断状態になります。自動再開はしません。
- タスクでCLIが報告した入力・出力トークン数を表示します。アカウント全体の残り利用枠や、正確なサブスクリプション使用率は取得しません。
- 既存会話の同期、他セッションの監視、バックグラウンドでの自動モデル実行は現在の対象外です。
- このフォルダーは独立したアプリです。他プロジェクトの中に置いても、親のGitリポジトリーやコードを管理しません。明示的に選択した作業フォルダーでの処理は別です。

Pretendard・Pretendard JP・JetBrains Monoは`public/fonts/`に同梱され、外部のフォントCDNなしで利用できます。SIL Open Font License 1.1のライセンス文と出典は[サードパーティーの表記](../THIRD_PARTY_NOTICES.md)を参照してください。

## 更新と配布の状況

ソースは非公開リポジトリー`Furu002/imperium-terminal`で管理します。公開配布用の[Furu002/imperium-releases](https://github.com/Furu002/imperium-releases)は現在空であり、ベンチマーク完了前に外部リリースは公開しません。v1.3.1は内部検証の対象です。**更新（F7）**には、パッケージ版アプリ、設定済み公開チャンネル、実際に公開されたリリースが必要です。ローカル専用モードでは更新のネットワーク要求を停止します。ダウンロードとインストールはユーザーの明示的な操作で行います。

Windowsのインストール版はNSIS更新、Linux AppImageはAppImage更新の経路を使用します。DEBは新しいパッケージを取得し、手動でインストールします。macOSは現在、署名証明書がないため手動更新が必要になる場合があります。ファイルのハッシュ検証はコード署名ではなく、**Sato Junichiro**の作成者メタデータも証明書による署名ではありません。ファイアウォールやOS全体のセキュリティ設定を無効にする手順は提供しません。

```sh
npm run desktop
```

Windowsで`npm run build:win`を実行すると、セットアップウィザードとポータブル版の両方を生成します。インストーラーだけを生成する場合は`npm run build:installer`を実行してください。macOSのDMG・ZIPは、Macで`npm run build:mac`を実行するか、GitHub ActionsのmacOSビルドを使用してください。LinuxのDEB・AppImageは、Linuxで`npm run build:linux`を実行するか、GitHub ActionsのUbuntuビルドを使用してください。成果物は`dist/`に生成されます。各プラットフォームのビルド成功状況はワークフローの実行結果で確認できます。

## 検証

```sh
npm ci --ignore-scripts
npm test
npm run check
```

テストはモックCLIを使い、実モデルを呼び出しません。このアプリのフォルダーをリポジトリーのルートとして公開した場合、付属のGitHub ActionsはUbuntu・Windows、Node.js 22・24で両コマンドを実行します。
