# IMPERIUM 구조와 검증 원칙

v1.3.0 내부 검증 대상의 설계 기록입니다. IMPERIUM은 사용자가 구성하고 명시적으로 실행하는 로컬 AI 작업 공간입니다. 빈 캔버스에서 본인·AI·역할·기억을 추가하며, 회사 조직 템플릿은 선택 사항입니다. 노드의 이름·직함·명찰은 사용자가 정합니다.

## 실행과 데이터 경계

화면에서 지시를 보내면 로컬 서버가 작업을 검증·대기열에 등록하고, 공식 CLI 또는 로컬 Ollama 어댑터가 실행합니다. 실시간 이벤트는 SSE로 전달합니다. 작업 정의와 캔버스 연결만으로 모델을 실행하지 않으며, 기존 ChatGPT·Claude 대화나 다른 터미널 세션을 관찰하지 않습니다.

| 범위 | 데이터·동작 |
| --- | --- |
| 프로젝트 | 실제 작업 폴더, 역할·에이전트 정의, 캔버스 배치·연결, 기억 검색 범위 |
| OS 사용자 | 공식 CLI 로그인과 프로젝트 간 공유되는 등록 모델 연결 |
| 작업 | 선택한 제공자·모델·권한, 결과·도구 이벤트, 보고된 토큰, 시작·첫 출력·종료 시각 |
| 터미널 | 사용자가 직접 제어하는 별도 셸. 앱의 입출력 버퍼는 제한된 RAM에 보관하며 작업·기억 내보내기에서 제외 |

프로젝트 생성은 새 폴더를 실제로 만들며 기존 폴더를 덮어쓰거나 이동하지 않습니다. 작업이 대기·실행 중이면 프로젝트 전환과 실행 환경 변경을 거절합니다. 프로젝트 구분은 데이터와 작업 문맥의 범위이며 별도의 OS 계정이나 보안 컨테이너를 만들지는 않습니다.

`settings.localOnly`를 켜면 모델 실행은 설치된 Ollama 로컬 모델로 제한하고, 클라우드 작업·클라우드 모델 조회는 HTTP 403으로 거절합니다. 데스크톱 업데이트의 네트워크 요청도 중단합니다. 이 기능은 실제 터미널에서 실행하는 외부 프로그램이나 OS 전체의 네트워크를 차단하는 방화벽이 아닙니다.

## 기억은 검색 가능한 프로젝트 자료

기억은 노트·결정·제약·실제 작업 결과를 저장하는 프로젝트 범위의 **키워드 RAG**입니다. 임베딩 API나 모델 가중치 학습을 사용하지 않습니다. 필요한 일부 자료를 초기 문맥으로 제공하고, Codex·Claude에는 작업 범위의 읽기 전용 MCP 도구 `memory_search`, `memory_get`, `memory_list`를 제공합니다. 작업이 끝나면 해당 조회 권한도 끝납니다.

자동 수집한 작업 결과는 `unverified`로 취급합니다. 지식 그래프의 연결은 검색과 탐색을 돕는 관계이며 내용의 진실성이나 인과관계를 증명하지 않습니다. 사람은 원문을 검토·수정하고 중요한 노트를 고정할 수 있습니다. 에이전트는 고정된 내용과 사용자 작성 자료를 덮어쓸 수 없으며, 고정 자체가 자동 사실 검증은 아닙니다.

## 계측과 추정의 구분

- 사용량·성능은 현재 프로젝트에서 보관 중인 실제 작업 기록에 근거합니다. DEMO는 제외하며 미보고 토큰은 누락으로 유지합니다. 구독의 남은 크레딧과 청구 절감액을 추정하지 않습니다.
- 지연은 시작→첫 출력, 실행 시간은 시작→종료로 측정합니다. p50·p95는 유효 표본의 nearest-rank 분위수입니다. 성공률의 분모는 완료와 실패 작업이며, 취소·중단·진행 중 작업을 성공으로 세지 않습니다.
- 토큰 비교는 같은 제공자·모델 ID·역할·권한에서 사용량이 모두 보고된 완료 작업 6개 이상을 시간순 동수 두 집단으로 나눕니다. 각 집단은 최소 3개이며 홀수 개의 가운데 표본은 제외합니다. 이는 관측값 비교로, 프롬프트 난이도나 코드 규모 등의 차이를 통제한 인과 실험이 아닙니다.
- 초기 문맥 문자 선별률과 추가 기억 조회량은 문자 기준 계측입니다. CLI 내부 문맥, 후속 조회, 토큰화와 실제 과금까지 반영한 절감률로 해석할 수 없습니다.
- 모델이 공개한 단계·진행률·ETA는 `model-estimate`, 유사한 과거 작업 시간은 `history` 추정으로 구분합니다. 내부 사고 과정을 추출하지 않습니다. 실행 중 추정치는 실제 완료를 대신하지 않으며 완료 확인 후에만 100%로 표시합니다.

## 설계 근거와 검증 범위

Anthropic은 여러 에이전트에 분명한 목표·출력·도구·경계를 주는 역할 분담과 실제 결과 평가의 중요성을 설명하며, 조정 비용과 토큰 사용 증가도 다룹니다. IMPERIUM의 역할 정의·명시적 업무 전달·실제 계측에 참고한 설계 근거입니다. 해당 시스템과 같은 자율 조정 구조나 성능을 구현했다는 주장은 아닙니다. [Anthropic: How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)

LangGraph의 기억 개념 문서는 대화 범위 상태와 세션 간 장기 기억을 구분하고, 장기 기억을 사용자 정의 namespace로 관리하는 방식을 설명합니다. IMPERIUM은 이 범위 구분을 참고해 프로젝트별 로컬 자료를 분리합니다. LangGraph 자체를 사용하거나 그 검색·학습 기능 전체를 제공한다는 뜻은 아닙니다. [LangGraph: Memory overview](https://docs.langchain.com/oss/python/concepts/memory) · [기존 문서 주소](https://langchain-ai.github.io/langgraph/concepts/memory/)

위 자료는 설계 선택의 근거이며 IMPERIUM의 벤치마크 결과가 아닙니다. 모의 CLI 테스트로 동작과 데이터 경계를 검사하고, 별도의 실제 작업 벤치마크로 결과 품질·오류·토큰·지연을 검증해야 합니다. 검증을 마치기 전에는 성능 향상·비용 절감·외부 배포 완료를 주장하지 않습니다. 소스 `Furu002/imperium-terminal`은 비공개이며 공개 배포 저장소 `Furu002/imperium-releases`에는 벤치마크 완료 전 릴리스를 게시하지 않습니다.
